# Система записи и учета скидок клиентов


## Где лежат паттерны

### Порождающие

* **Строитель** (`booking_service/appointment_builder.py`) — аккуратно собирает финальную запись клиента. Следит, чтобы клиент не списал баллов больше, чем положено.
* **Фабричный метод** (`loyalty_service/transaction_factory.py`) — создает операции с баллами (начисление/списание). Проверяет, хватает ли у клиента баланса перед списанием.

### Структурные

* **Фасад** (`booking_service/booking_facade.py`) — делает нам удобно. Вызываем всего один метод, а он сам лезет за скидкой, сохраняет бронь и дает команду отправить СМС.
* **Заместитель / Proxy** (`loyalty_service/cached_rules_proxy.py`) — один раз скачивает правила скидок из базы и держит их в памяти. Так система работает гораздо быстрее.
* **Адаптер** (`notification_service/senders_adapter.py`) — нужен для отправки сообщений. Помогает легко менять сервисы рассылок (СМС, Телеграм), ничего не ломая в нашем основном коде.

### Поведенческие

* **Стратегия** (`loyalty_service/pricing_strategy.py`) — считает, сколько клиент должен заплатить. Сейчас считает по его уровню, но можно в два счета добавить логику для промокодов.
* **Состояние** (`booking_service/appointment_state.py`) — жестко следит за статусами. Если услуга уже оказана, он ни за что не даст её отменить.
* **Наблюдатель** (`loyalty_service/loyalty_observer.py`, `notification_service/event_listener.py`) — сидит и ждет завершения визита. Как только визит окончен, он автоматически начисляет кэшбэк и отправляет чек клиенту.
