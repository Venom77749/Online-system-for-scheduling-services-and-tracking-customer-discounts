# Система записи и учета скидок клиентов (2 микросервиса + SQLite)

Проект разделен на два независимых FastAPI-приложения, каждое со своей локальной базой данных **SQLite** (встроенной в Python — ничего дополнительно устанавливать не нужно):

1. **`booking_app` (порт `8001`, БД `booking_app/booking.db`)** — управление записями (паттерны: Builder, State, Facade).
2. **`loyalty_app` (порт `8002`, БД `loyalty_app/loyalty.db`)** — расчет скидок, бонусные транзакции и уведомления (паттерны: Proxy, Strategy, Factory Method, Observer, Adapter).

## 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

## 2. Запуск двух приложений

Откройте два терминала:

**Терминал 1 (`loyalty_app`, порт 8002):**
```bash
cd loyalty_app
uvicorn main:app --port 8002 --reload
```

**Терминал 2 (`booking_app`, порт 8001):**
```bash
cd booking_app
uvicorn main:app --port 8001 --reload
```

> При первом запуске файлы баз данных `booking.db` и `loyalty.db`, все таблицы и тестовые данные (правила скидок + клиент `client-101` с 35 000 ₽ трат и 400 баллами) создадутся автоматически.

## 3. Проверка работы

В третьем терминале запустите демонстрационный сценарий:
```bash
python demo_client.py
```

Также доступны интерактивные Swagger-интерфейсы:
- Booking Service: http://127.0.0.1:8001/docs
- Loyalty & Notification Service: http://127.0.0.1:8002/docs

## Паттерны

### Порождающие

- **Строитель** (`booking_app/appointment_builder.py`) — собирает финальную запись клиента. Следит, чтобы клиент не списал баллов больше, чем положено.
- **Фабричный метод** (`loyalty_app/transaction_factory.py`) — создает операции с баллами (начисление/списание). Проверяет, хватает ли у клиента баланса перед списанием.

### Структурные

- **Фасад** (`booking_app/booking_facade.py`) — вызывает один метод, берет скидку, сохраняет бронь и отправляет СМС.
- **Прокси** (`loyalty_app/cached_rules_proxy.py`) — один раз скачивает правила скидок из базы и держит их в памяти.
- **Адаптер** (`loyalty_app/senders_adapter.py`) — нужен для отправки сообщений. Помогает легко менять сервисы рассылок (СМС, Телеграм), ничего не ломая в основном коде.

### Поведенческие

- **Стратегия** (`loyalty_app/pricing_strategy.py`) — считает, сколько клиент должен заплатить. Сейчас считает по его уровню, позже можно добавить логику для промокодов.
- **Состояние** (`booking_app/appointment_state.py`) — следит за статусами. Если услуга уже оказана, он не даст её отменить.
- **Наблюдатель** (`loyalty_app/loyalty_observer.py`, `loyalty_app/event_listener.py`) — как только визит окончен, автоматически начисляет кэшбэк и отправляет чек клиенту.
