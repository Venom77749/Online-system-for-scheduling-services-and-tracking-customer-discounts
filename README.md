# Система записи и учета скидок клиентов (2 микросервиса + SQLite + CustomTkinter GUI)

Проект разделен на два независимых FastAPI-приложения со своими базами данных **SQLite** и графическим интерфейсом на **CustomTkinter**:

1. **`booking_app` (порт `8001`, БД `booking_app/booking.db`)** — управление записями (паттерны: Builder, State, Facade).
2. **`loyalty_app` (порт `8002`, БД `loyalty_app/loyalty.db`)** — расчет скидок, бонусные транзакции и уведомления (паттерны: Proxy, Strategy, Factory Method, Observer, Adapter).
3. **`gui.py`** — десктопное приложение на CustomTkinter для удобной работы с обоими микросервисами.

## 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

## 2. Запуск с графическим интерфейсом (самый простой способ)

Запустите `gui.py`:
```bash
python gui.py
```
В правом верхнем углу окна нажмите зеленую кнопку **«Запустить сервисы»** — приложение само поднимет оба микросервиса (`:8001` и `:8002`), создаст базы `booking.db` и `loyalty.db` с тестовым клиентом `client-101` (35 000 руб. трат, 400 баллов) и отобразит зеленые индикаторы `Online`.

*(При желании оба микросервиса можно запустить и отдельно в двух терминалах — GUI автоматически к ним подключится.)*

**Терминал 1 (`loyalty_app`, порт 8002):**
```bash
cd loyalty_app
python -m uvicorn main:app --port 8002 --reload
```

**Терминал 2 (`booking_app`, порт 8001):**
```bash
cd booking_app
python -m uvicorn main:app --port 8001 --reload
```

## 3. Проверка через консольный скрипт (опционально)

```bash
python demo_client.py
```

## Паттерны

### Порождающие

- Строитель (`booking_app/appointment_builder.py`) — собирает финальную запись клиента. Следит, чтобы клиент не списал баллов больше, чем положено (не более 50%).
- Фабричный метод (`loyalty_app/transaction_factory.py`) — создает операции с баллами (начисление/списание). Проверяет, хватает ли у клиента баланса перед списанием.

### Структурные

- Фасад (`booking_app/booking_facade.py`) — вызывает один метод, берет скидку, сохраняет бронь и публикует событие.
- Прокси (`loyalty_app/cached_rules_proxy.py`) — один раз скачивает правила скидок из базы и держит их в памяти.
- Адаптер (`loyalty_app/senders_adapter.py`) — нужен для отправки сообщений. Помогает легко менять сервисы рассылок (СМС, Телеграм), ничего не ломая в основном коде.

### Поведенческие

- Стратегия (`loyalty_app/pricing_strategy.py`) — считает, сколько клиент должен заплатить. Сейчас считает по его уровню, позже можно добавить логику для промокодов.
- Состояние (`booking_app/appointment_state.py`) — следит за статусами. Если услуга уже оказана, не даст её отменить.
- Наблюдатель (`loyalty_app/loyalty_observer.py`, `loyalty_app/event_listener.py`) — как только визит окончен, автоматически начисляет кэшбэк 5% и отправляет чек клиенту.
